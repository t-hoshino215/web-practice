# TDD (Test-Driven Development)

全ての機能実装は、Kent Beckやt-wadaが提唱するテスト駆動開発（TDD）の手法に従って、テストファーストのコード実装・変更を行う。

---

## 実装プロセス

必ず以下の順序で機能実装を行う
Step 2 から Step 5 は、タスクごとに繰り返す

### Step 1: **事前確認**

1. $ARGUMENTS が指定されていればその内容を確認し、計画書のファイルパスがあれば `Read` で内容を理解する
2. $ARGUMENTS がない場合は、`docs/plans` ディレクトリ内の関連する計画書を `Glob` と `Grep` で検索して特定し、内容を `Read` して理解する
3. 該当する計画書が見つからない、または内容が不十分な場合は、軽微な変更であればタスクを列挙して作業を進め、変更が大きいは場合は実装を開始せずにメインセッションに報告して、ユーザーに確認する
4. 以下のフォーマットでタスクの進捗を提示する

```text
## Implement Tasks

計画書 `{ファイルパス}` の実装 (計画書が見つからない場合: ユーザーの要求に基づいてタスクを実行 {要求内容の要約})

- [x] `{タスク名1}`: (完了した場合、コミットハッシュなどの証拠があれば記載)
- [ ] `{タスク名2}`: (実行中の場合、どのステップにいるか記載 {RED/GREEN/REFACTOR/COMMIT})
- [ ] `{タスク名3}`: Not-Started
...
```

変更の規模の判断基準:

- **軽微な変更**: 1-2ファイルの変更で、既存のコードパターンやテスト方針に従って実装できるもの。例: 既存の関数に引数を追加する、既存のクラスにメソッドを追加するなど。
- **大きな変更**: 3ファイル以上の変更が必要、または既存のコードパターンやテスト方針では対応できないもの。例: 新しい機能の追加、既存の機能の大幅な変更、アーキテクチャの変更など。

### Step 2: **テスト作成（RED）**

- 最初に失敗するテストケースを追加する
- すべてのエッジケース、エラーシナリオ、境界条件を網羅する
- 単体テスト、統合テスト、E2Eテストを適切に組み合わせる
- テストが失敗することを確認する

### Step 3: **コード実装（GREEN）**

- テストをパスするための最小限のコードを実装する
- 既存コードの変更は最小限に抑える
- コードがテストをパスすることを確認する

### Step 4: **リファクタリング（REFACTOR）**

- テストがパスする状態を維持しながら、コードを改善する
- 振る舞いを変えずに構造だけを改善する
- コードの可読性、保守性、パフォーマンスを向上させる

確認する観点:

- 重複コードの抽出
- 命名規則の遵守
- 関数の責務が1つになっているか
- ネストが3段以内か

### Step 5: **コミット**

- Git管理されたプロジェクトの場合、タスクごとに変更をコミットする
- コミットフローは `.claude/skills/smart-commit/SKILL.md` に従う

### Step 6: **実装完了報告**

全てのタスクが完了したら、変更内容のサマリーを以下のフォーマットで提示する。

```text
| タスク名 | ステータス | 変更ファイル | コミットID |
| --- | --- | --- | --- |
| `{タスク名1}` | Completed | `{変更ファイル1, 変更ファイル2, ...}` | `{コミットID}` |
| `{タスク名2}` | Completed | `{変更ファイル1, 変更ファイル2, ...}` | `{コミットID}` |
...
```

## Best Practices

1. **Write Tests First** - 常にTDD
2. **One Assert Per Test** - 単一の振る舞いに集中
3. **Descriptive Test Names** - 何を検証するか明確にする
4. **Arrange-Act-Assert** - 明確なテスト構造
5. **Mock External Dependencies** - 単体テストを分離
6. **Test Edge Cases** - Null、undefined、空、大量データ
7. **Test Error Paths** - 正常系だけでなく異常系も
8. **Keep Tests Fast** - 単体テストは各50ms未満
9. **Clean Up After Tests** - 副作用を残さない
10. **Review Coverage Reports** - 抜け漏れを特定する

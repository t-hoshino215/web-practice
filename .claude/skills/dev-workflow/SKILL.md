# Development Workflow Orchestrator

計画・実装・レビュー・記録の4フェーズの各スキル・サブエージェントを統合して、コード変更の全体的な開発フローを管理する。

## 基本原則

- $ARGUMENTS で受け取った機能概要を起点に、以下の4フェーズを順番に実行する。
- 計画から実装に進む際に、ユーザー承認を得てから次に進む。
- 承認が得られない場合は止まって指示を待つ。
- 計画から実装に進む際に、中断・再開が可能。

---

## Phase 0: 開始宣言

以下の形式でワークフローの開始をユーザーに宣言する。

```text
========================================================
dev-workflow
> リクエスト: {$ARGUMENTS}
> 想定フェーズ: 要件定義 → 実装 → レビュー → 記録
> 各フェーズの完了時に承認を求めます。
========================================================
```

---

## Phase 1: 要件定義と計画

`/planning` スキルの手順に従って以下を実行する。

### Planning スキル実行

1. コードベースを調査する（Glob / Grep / Read）
2. 不明点があればユーザーに確認する
3. 実装計画書を `docs/plans/YYYYMMDD-HHMMSS_{機能名}.md` に作成する

### 計画完了時の報告と承認要求フォーマット

計画書が作成されたら、以下の形式でユーザーに報告し、承認を求める。

```text

報告・承認フォーマット:

```text
Phase 1: 計画作成
実装計画書: {実装計画書のファイルパス}

この内容で実装フェーズに進んでよいですか？
> - a. 承認 → 「a」または「OK」と返答
> - b. 修正 → 変更したい点を指示
> - c. 中断 → 「c」または「中断」と返答
```

返答を待つ。承認されたら次のフェーズに進む。修正指示があれば計画書を更新して再度提示する。中断があればワークフローを停止する。

---

## Phase 2: 実装

`@tdd-implementer` サブエージェントを起動する。

### 実装サブエージェントへの指示

下記の内容をサブエージェントに渡して実装を依頼する。

```
承認済み計画書 docs/plans/{ファイル名} に従って実装を進めてください。
完了時に以下を報告してください:

変更ファイルの一覧
追加したテストの件数と結果
コミットのハッシュ
```

### 実装完了の報告と承認要求フォーマット

Agent の完了報告を受け取ったら、以下の形式でユーザーに要約を提示して次のフェーズへ進む。

```text
Phase 2: 実装完了

- 変更ファイル: {一覧}
- テスト: {結果}
- コミット: {ハッシュ}

> 続けてレビューフェーズに進みます。
```

---

## Phase 3: レビュー

`@code-reviewer` サブエージェントを起動する。

### レビューサブエージェントへの指示

下記の内容をサブエージェントに渡してコードレビューを実行する。

```text
フェーズ2で実装されたコードをレビューしてください。
対象ファイルは docs/plans/{ファイル名} の「影響範囲」を参照。
共通ルール（rules/code-review-guide.md）と言語別ルールに従って問題を報告してください。
```

Agent のレビュー結果を受け取ったら、ユーザーに提示する。

### 問題がある場合の対応

1. `@tdd-implementer` を再起動して指摘内容を渡し修正を依頼する
2. 完了後に再度 `@code-reviewer` でレビューする
3. CRITICAL・HIGH がなくなるまでこのループを繰り返す（最大3回）
4. 3回ループしても解消しない場合はユーザーに判断を求める

---

## Phase 4: 記録

`@tdd-implementer` サブエージェントを起動する。

### 記録サブエージェントへの指示

下記の内容をサブエージェントに渡して作業ログの作成を依頼する。

```
下記の作業内容をもとに、docs/logs/ に作業ログを作成してください。

- 計画書: docs/plans/{ファイル名}
- 実装: {Phase 2 の最終的な完了報告内容}
- レビュー結果: {Phase 3 の最終的なレビュー結果}
```

## Phase 5: 完了報告

フローが完了したら、以下の形式でユーザーに報告する。

```text

dev-workflow 完了

- 計画書: docs/plans/{計画書ファイル名}
- 作業ログ: docs/logs/{作業ログファイル名}
- コミット: {ハッシュ一覧}

全てのフェーズが完了しました。お疲れ様でした！
```

---

## 中断時の振る舞い

ユーザーが「中断」と返答した場合、または以下の条件に該当した場合は
フローを止めて状態を保全する。

- 実装済みのコミットはそのまま残す（rebase しない）
- 以下の再開方法を報告する

```text
フローを中断しました。

現在の状態:
- 計画書: {status}
- 実装: {完了タスク数 / 全タスク数}
- レビュー: {未実施 / 実施済み}

> 再開するには `/dev-flow 再開` と入力してください。
```

## 再開の処理

$ARGUMENTS に「再開」が含まれる場合は、最新の計画書を読み、指示内容応じて適切なフェーズから再開する。

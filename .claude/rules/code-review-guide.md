# Code Review Standards

## 目的

全てコードの作成・変更の際に、適用するコードレビュー基準を定義する。
マージ前に品質・セキュリティ・保守性を確保し、問題のあるコードを修正する。

---

## 優先度の定義

| 優先度 | 意味 | 対応 |
| --- | --- | --- |
| CRITICAL | セキュリティ脆弱性またはデータ損失のリスク | **BLOCK** - 修正するまでマージ不可 |
| HIGH | バグまたは重大な品質問題 | **WARN** - 原則マージ前に修正 |
| MEDIUM | 保守性の懸念 | **INFO** - 修正を検討 |
| LOW | スタイルや軽微な指摘 | **NOTE** - 任意 |

---

## レビュー観点

### CRITICAL: セキュリティ

下記は実害が生じる可能性があるため、必ず `CRITICAL` フラグを立てる：

- **ハードコードされた認証情報** — ソースコード内のAPIキー、パスワード、秘密鍵など
- **SQLインジェクション** — パラメータ化クエリではなく文字列連結によるクエリ
- **クロスサイトスクリプティング（XSS）** — HTMLやJSXでエスケープされていないユーザー入力のレンダリング
- **パストラバーサル** — サニタイズなしのユーザー制御ファイルパス
- **CSRF脆弱性** — CSRF保護のない状態変更エンドポイント
- **認証バイパス** — 保護されたルートの認証チェックの欠如
- **脆弱な依存関係** — 既知の脆弱なパッケージ
- **ログに秘密が露出** — トークン、パスワード、PIIなどのログ出力

```typescript
// BAD: 文字列連結によるSQLクエリ
const query = `SELECT * FROM users WHERE id = ${userId}`;

// GOOD: パラメータ化クエリ
const query = `SELECT * FROM users WHERE id = $1`;
const result = await db.query(query, [userId]);
```

### HIGH: コード品質

- **大きすぎる関数**（50行超）— より小さく、単一責任の関数に分割する
- **大きすぎるファイル**（800行超）— 責任ごとにモジュールを分割する
- **深いネスト**（4段階超）— 早期リターンやヘルパー関数を活用する
- **エラーハンドリングの欠如** — 未処理のPromiseリジェクション、空のcatchブロック
- **ミューテーションパターン** — イミュータブルな操作（スプレッド・map・filter）を優先する
- **console.logの残留** — デバッグ用のログはマージ前に削除する
- **テストの欠如** — テストカバレッジのない新しいコードパス
- **デッドコード** — コメントアウトされたコード・未使用のインポート・到達不能なブランチ

```typescript
// 悪い例：深いネスト + ミューテーション
function processUsers(users) {
  if (users) {
    for (const user of users) {
      if (user.active) {
        if (user.email) {
          user.verified = true;  // ミューテーション！
          results.push(user);
        }
      }
    }
  }
  return results;
}

// 良い例：早期リターン + イミュータビリティ + フラットな構造
function processUsers(users) {
  if (!users) return [];
  return users
    .filter(user => user.active && user.email)
    .map(user => ({ ...user, verified: true }));
}
```

### MEDIUM: 保守性

- **複数責務** — 1つの関数が明らかに複数の責務を持っている
- **マジックナンバー** — 説明のない数値定数
- **ロジック重複** — 同じロジック、同じ機能を持つコードの重複

### MEDIUM: パフォーマンス

- **非効率なアルゴリズム** — O(n log n) や O(n) が可能なところでO(n²)を使用している
- **不必要な再レンダリング** — React.memo・useMemo・useCallbackの欠如
- **大きなバンドルサイズ** — ツリーシェイク可能な代替手段があるのにライブラリ全体をインポートしている
- **キャッシュの欠如** — メモ化なしで重い計算を繰り返している
- **最適化されていない画像** — 圧縮や遅延読み込みのない大きな画像
- **同期I/O** — 非同期コンテキストでのブロッキング処理

### LOW: ベストプラクティス

- **チケットのないTODO/FIXME** — TODOにはイシュー番号を参照すること
- **パブリック関数のドキュメントの欠如** — JSDocやdocstringなどのドキュメントのないエクスポート関数
- **不適切な命名** — 非自明なコンテキストでの一文字変数（x・tmp・data）
- **一貫性のないフォーマット** — セミコロン・クォートスタイル・インデントの混在
